# Dual-stack routing evidence

Continue the authorized network-isolation step using the existing Linux namespace laboratory. Extend it with IPv4/IPv6 HTTP, UDP echo and real DNS TXT queries over UDP/TCP, usable fallback controls, forced fallback while the assigned interface remains up, and three disconnect/recovery cycles. A sibling profile stays reachable throughout. Each blocked probe must time out while the namespace firewall's named drop counter increases; connection errors are not successful blocking evidence.

The existing local namespace approach is retained because it already isolates lab routes/firewalls from the host. External test sites add dependency and disclose test activity; a production privileged supervisor is a separate subsystem requiring provider tunnels and real browser testing. This lab uses simulated tunnels and cannot enable application launches.

Version-2 evidence must contain exactly eight family/protocol cases, strict successful source addresses for both profiles and fallback, all controls and all three cycles. Legacy, malformed, missing and duplicate observations fail assessment. Probe responses must correlate to fresh request nonces; DNS must use valid wire messages. CLI failures stay explicit and never become a blocked observation.

No host route/firewall edits. Namespaces and temporary down/unaddressed veth links are owned and cleaned by the invocation. Cleanup failure makes the run fail. Privileged execution requires --run and successful preflight. Missing capabilities yield exit 2 with blocked evidence, never a pass. Local unprivileged socket tests validate fixtures and evidence evaluation; they are not OS-isolation proof.

No dependencies or product UI changes. Networked launches remain hard-blocked. Linux namespace runtime validation is unavailable in this executor; the report and docs must retain that limitation.
