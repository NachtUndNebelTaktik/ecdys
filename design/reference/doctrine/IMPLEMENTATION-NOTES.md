# Doctrine traceability and verification

The user's `EcDys-Design-Doctrine.md` governs the interface. This implementation uses the same behavior and layout in dark and light modes. It does not claim to implement the underlying browser-security architecture.

| Principle | Implemented consequence | Practical limit |
| --- | --- | --- |
| Witness, not performer | Counts come from current arrays; timestamps are recorded when actions occur; opening and downloads are described as requests. No simulated work or protection metrics. | The activity record observes only actions handled by this preview. Context-menu navigation and external page completion cannot be established. |
| Every boundary is drawn | Persistent execution/memory/vault context; destination review shows normalized URL, recipient, query and protocol requested; external-opening control states the boundary. | Current browser route, cookies, isolation and host observation are not inspected. A URL's HTTPS scheme is a request, not verification of a connection. |
| Calm under load | Neutral frame, small consistent type scale, no loops or transition animations; crimson marks selected navigation and consequential external/destructive actions. | No performance claim is made about live high-volume streams; this preview does not implement them. |
| Structure over decoration | Three functional start paths and a labelled working example; no central hero logo, slogans, gradients, illustrative art, glass effects or shadows. One radius and border token. | The UI remains a component prototype rather than a complete native browser shell. |
| Nothing that matters is hidden | Retention is visible; exports start with no scopes selected; capabilities and limitations are named; removal confirmation lists actual counts. | Export contains only committed workspace collections, not unfinished bookmark input drafts. Drafts are retained across dialog cancellation and cleared by workspace clearing/reload. |
| Reversibility with weight | Notes, bookmarks, destinations and layout changes have up to 30 undo snapshots. Clearing drops content/history after a consequence-specific review. | Undo expires as older changes leave the bounded history; it does not reverse external navigation or erase browser/host records. |
| Operator ownership | Notes, bookmark management, selectable export, adjustable panels, context docking and real light/dark mode work without an account requirement in the component. | Durable session recovery, arbitrary floating windows and layout import are not implemented. The hosting platform is outside the component's account policy. |
| Language as a material | Errors state what happened, the effect, and the next action. No celebratory voice or unverifiable security claims. | Future backend events must supply provenance and actual capability states before the corresponding labels can change. |

## Visual tokens

- Accent: `#dc143c`.
- Dark grounds: `#101214`, `#17191c`, `#202327`.
- Dark text: `#e8eaec`; secondary text: `#a6adb5`.
- Light grounds: `#f5f6f6`, `#ffffff`, `#e8ebed`.
- Light text: `#171b1f`; secondary text: `#58636d`.
- Control radius: 4 px. Border: 1 px. No shadow level. No animation.
- Label/prose register: humanist system sans stack.
- Values, identifiers, URLs and timestamps: system monospace stack.

Calculated sRGB contrast checks on declared tokens: dark body text 15.56:1, dark secondary text on raised surface 6.96:1, light body text 15.99:1, light secondary text on raised surface 5.13:1, white on crimson 4.99:1. These checks concern the specified token pairs, not a complete accessibility certification.

## Logic checks

The 10 boundary/export checks cover URL normalization, host/port recognition, unsupported schemes, credentials, malformed URLs, exact query encoding, empty/control-character input, unselected export, granular scope exclusion, mutation/property leakage and invalid timestamps.

The 9 workspace checks cover initialization, restoration of removals and layout, grouped typing, action grouping boundaries, activity preservation, empty undo, the 30-snapshot cap, clearing, and immutable state behavior.

Both compiled dark/light previews were visually inspected. A complete interaction audit on all viewport sizes, a native browser integration test and a security audit remain separate work.
